# Contributing

No pull requests are accepted in v1. Issues are open for discussion only — not support, and never clinical advice.

**Why.** `epppsynth` is a personal, local tool published as a source and design artifact, not a product (D-33). Accepting code into a safety-argued artifact with no capacity to review it would weaken the argument the artifact exists to make (D-34) — and there is no capacity: review is author-only, and no clinician, educator, ethicist, security assessor, or accessibility reviewer has read any of it (D-27).

**What would change it.** A contributor attestation (DCO or equivalent) and a pull-request intake process are revisited once recruited, role-identified reviewers exist; recruitment opens when an engine runs end-to-end, *planned — EP-37*. Until then the useful contribution is an issue saying where the design, the governance, or a public claim is wrong.

Security, safety, and leak concerns go privately through [`SECURITY.md`](SECURITY.md) instead. Conduct: [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md). What is kept and what is not: [`PRIVACY.md`](PRIVACY.md). What the tool refuses to do: [`SAFETY.md`](SAFETY.md).
